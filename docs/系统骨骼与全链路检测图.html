四、本次修掉的 5 个硬伤（含"为什么一直没被发现"）

① 渠道名对不上 —— 能力清单与更新结论从未生效

客户端 runtimeTag() 返回 mp-weixin / h5 / app，服务端 APP_CHANNELS 只认 wechat / web / android|ios。线上 ?channel=mp-weixin 直接 400 E_UNKNOWN_CHANNEL，客户端见 ok:false 就返回 null，静默退回静态清单。

为什么没被发现：接口能连通、客户端设计成"拿不到就兜底"、功能表面正常 —— 两端各说各的名字，人工点不出来，只能靠断言。现由 check-channel-contract.mjs 守住。

② 缓存指纹从来没进过线上

指纹注入只写在 package-static.ps1（打 ZIP 用），而线上真跑的是 sync-static-from-windows.ps1（scp 到源站）—— 那条路没有注入。于是线上首页从来没有 ?v=，CSS/JS 无法长缓存。

为什么没被发现：检查器 check-cache-policy 一直在报红，但它是"在线检查"的最后一项，容易被当成环境问题跳过。修法是抽出 inject-asset-version.ps1 让两条通道共用，并在远端 grep 断言 ?v= 存在。

③ 桌面自动更新指向一个不存在的文件

线上 latest.yml 写的是 Q问-Setup-1.0.6.exe（公网 404），真实包是 qtvq-desktop-Setup-1.0.6.exe；连 size 都差 8 字节（82788539 vs 82788547），sha512 也对不上。

为什么没被发现：下载页读的是另一份配置（download-config.js），手动下载一切正常；只有客户端自动更新会失败，而失败是静默的。上传脚本原来只校验"文件能下载、大小对得上"，没校验"清单里引用的那个文件是否存在"。

④ 统一升级只有 3/14 渠道有记录

其余 11 个渠道走兜底 latest: 1.0.0 —— 比客户端真实的 1.0.6 还低。发版时这些端拿到的仍是"已最新"，等于没发。

补齐 11 条（8 小程序 + web + 已有 windows/wechat）。Android/iOS/鸿蒙没有安装包，刻意不给记录：给了 version 就必须给 downloadUrl，否则就是"提示有新版但点不动"的假更新。豁免理由写进 JSON 的 _未发布渠道，由检查器核对。

⑤ H5 产物不在发布流水线里

改了源码、重建了 H5，但没有任何脚本负责上传，线上 /h5/ 停在 9 月那一版 —— 手机上打开网页版，看到的界面与小程序不一致。

现在 sync-static 会把 dist/build/h5 一并发布（含远端 test -f h5/index.html 断言）；产物不存在时明确告警而不是静默跳过。

六、死循环 / 空链接 / 漏洞排查结果

项排查方式结论
死循环 扫 setInterval/setTimeout 自递归、while(true)、for(;;)、重试无退避 4 处无限循环均有边界：报告轮询（120s 上限 + 1.5s 间隔）、SMTP 读响应（读到完成码即返回）、H5 轮询（10 分钟/次，单次提示）
无意义轮询 检查后台标签页是否仍在打请求 已修 account 页 30s 轮询改为 document.hidden 跳过，切回时补一次
空链接 32 个内链本地存在性 + 线上 HEAD + audit-dead-ends 内链 0 缺失；下载页 10 个未上线入口渲染成 disabled（不产生可点空 href）
空 src 扫 src="" 已修 首页收款码图片原为 src=""（会让浏览器重请求当前文档），改为无 src + hidden
越权 / 鉴权 逐路由看 requireAuth；线上探测未登录响应 敏感接口未登录一律 401（非 404/500，不泄露存在性）；admin 组在未配 ADMIN_KEY 时整组 404
注入 84 处 innerHTML 逐类核对转义 用户/模型内容走 escapeHtml/esc；新增内容一律先转义再拼接
密钥泄露 扫 PEM / sk- / AKIA / LTAI；Pages 泄露自检 命中的都是 PEM 格式化函数，非真私钥；部署后 9 个敏感路径全 404
CORS 看白名单是否 * 严格白名单（qtvq.cn / www / api 子域 / 本地调试），拒绝时返回 403 而非放行
SEO 卫生 sitemap 与页面清单对比 已修 补 advice/report/wheel/terms 4 页，去掉与 / 重复的 index.html
