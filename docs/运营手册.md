# Q问 · 运营手册（收款与会员）

> 这份手册只回答一件事：**客户付钱前后，你要做什么。**
> 面向运营者（非技术），每条都写明"去哪儿、点什么、看到什么算成功"。
> 最后更新：2026-09-18

---

## 一、三条收款路径：谁自动、谁要你动手

| 路径 | 入口位置 | 钱到哪 | 谁开会员 / 加缘值 | 你要做的事 |
| --- | --- | --- | --- | --- |
| **① 微信在线支付**（推荐） | 会员页蓝色主按钮 / 我的账户→缘值充值 | 微信商户号 **1113936939** | **系统全自动**（付完几秒内） | **什么都不用做**，只会收到一封抄送邮件 |
| **② 静态收款码** | 会员页 → 折叠区「没有微信？」 | 你的微信/聚合收款账户 | 人工核实后开通 | 收到邮件 → 去审核页点一下（约 30 秒） |
| **③ 对公银行汇款** | 会员页 → 折叠区「对公银行汇款」 | 公司工行账户 | 人工核实后开通 | 同上 |

**结论**：把客户尽量引到 ①，你的日常工作量≈0。②③ 只作为少数客户的兜底。

## 二、收到「[Q问待核实]」邮件后怎么做（30 秒）

### 第 1 步：打开审核页

```
https://qtvq.cn/tools/verify-payment.html
```

> 备用地址：`https://qtvq-api.pages.dev/tools/verify-payment.html`（两个是同一个页面）

### 第 2 步：输入运营口令

口令保存在你电脑上的文件里：

```
D:\qtvq\.dev.vars
```

用记事本打开，找到 **`PAYMENT_ADMIN_KEY=`** 这一行，等号后面那串就是口令（36 位）。
**不要**把口令发给客户，也不要用微信/邮件传递。

### 第 3 步：核对到账

页面会列出待核实记录，逐项核对：

- 付款人姓名 → 与你的收款记录（微信账单 / 银行流水）对上
- 金额 → 与所选套餐一致（月卡 ¥29 / 季卡 ¥79 / 年卡 ¥299）
- 付款时间 → 大致相符
- 备注 / 后四位 → 客户填的设备编号或账单后四位

### 第 4 步：点「核实并开通」

点下去之后：该客户**立刻**变成会员，界面会返回 `已核实汇款，提问已解禁` ✅

> **对不上账怎么办**：先别点。邮件里有客户的**绑定手机号**和**设备编号**，用它联系客户确认（常见原因：金额填错、只付了一部分、把两笔合并付了）。

## 三、缘值充值（转盘 / 配对报告用的余额）

### 自动入账（推荐路径）

客户走「我的账户 → 缘值充值 → 微信在线支付」时，**付完自动加缘值**，你什么都不用做。
你只会收到一封标题为 `[Q问收款] 缘值充值 ¥X 已到账并自动入账` 的抄送邮件。

### 人工入账（客户走了静态码时）

如果客户用静态收款码充值，邮件标题是 `[Q问待核实] 缘值充值 ¥X`，此时需要你手动加余额：

1. 打开运营台：`https://qtvq.cn/v1/admin/console`
2. 口令同上（`server/.env` 里的 `ADMIN_KEY`，与付款核实口令**不是同一个**）
3. 找到该用户（按邮件里的**绑定手机号**或设备编号搜索）
4. 用「入账」功能加上对应金额，备注写订单号便于日后对账

> ⚠️ **缘值与会员费是两笔钱**：会员费买权益（不增缘值），缘值只能用于转盘（每次 ¥1）与配对报告。
> 给客户加缘值 ≠ 给他开会员，两件事分开做。

## 四、客户说"付了钱网站没反应"怎么办（按顺序查）

| 顺序 | 你要问 / 要做的 | 判断 |
| --- | --- | --- |
| 1 | 问他走的哪条路：**在线支付**（扫码前有没有先点蓝色按钮）还是**静态收款码**？ | 静态码本来就不会自动识别 → 让他点「我已付款 · 提交核实」 |
| 2 | 让他把**订单号**（`ord_` 开头）发你 | 有订单号我就能直接查微信侧的权威交易状态 |
| 3 | 若无订单号 → 说明是通过静态码付的 → 走第二节的核实流程 | |
| 4 | 若是在线支付且订单号显示未支付（NOTPAY）→ 说明他扫了码但**没完成付款** | 让他重新扫一次 |

**兜底逻辑（已内置）**：在线支付即使回调延迟，客户**下次打开账户页**时系统会主动向微信查账并**自动补开通/补入账**。
所以让客户"刷新一下账户页"往往就能解决。

## 六、AI 问答/报告用的是哪个模型（2026-09-18 起）

**现在用的是阿里云百炼（通义）的角色模型 `qwen-plus-character`**，出问题时自动降级到
Workers AI（境外但已绑定、不额外计费），最后才用内置话术兜底。

| 位置 | 管什么 | 现在用的模型 |
| --- | --- | --- |
| 网站/小程序的「Q问」问答 | 用户提问的回答 | 百炼 `qwen-plus-character` → `qwen-long` → Workers AI 三个模型 |
| 配对报告正文 | 付费报告的内容 | 同上（**报告侧需服务器执行一次配置后才生效**，见下） |
| 避坑检索（RAG）向量 | 找相关案例 | Workers AI（未改；换它要重建索引，见技术方） |

**一条命令看"现在到底谁在答"**（技术方或按需问技术方）：

```
node tools/scripts/check-llm.mjs
```

会打印整条链、每一环是否就绪、以及真实探测命中的 provider/model。

### 关于"通义星辰"（tongyi.aliyun.com/character/）

**那个页面不能直接调用** —— 它是通义 App 的角色页，没有公开 API
（拿那种角色编号当应用 ID 调会返回 `403 App.AccessDenied`）。要"在后台配好人设的角色"，
需要在**阿里云百炼控制台**建「角色应用」；或者用现在的做法：把角色人设写在提示词里，
用百炼的角色扮演模型 `qwen-plus-character`。

### 换模型 / 充值怎么操作

- **充值**：阿里云控制台（同一个账号里已经有短信、OSS、语音、向量检索）——
  **一个账号一个账单，支付宝充值即可**。
- **百炼免费额度用尽会怎样**：报错 `Free quota exhausted`，此时 `qwen-plus`/`qwen-turbo` 等
  主流模型不可用（`qwen-long`、`qwen-plus-character` 可能仍有额度）。
  解决：百炼控制台 → 费用与配额 → **关闭"仅使用免费额度"**或充值。
- **想换成别的模型**：技术方改一个环境变量 `LLM_CHAIN`（形如
  `tongyi:qwen-plus-character,tongyi:qwen-long,workers-ai:@cf/...`），不用改代码。

## 七、遇到问题找谁

- **支付类**（付了没开通、金额不对、要退款）：把客户订单号（`ord_` 开头）发技术方，可直接查微信侧状态
- **账号类**（登录不了、忘记密码、要注销）：客户可在「我的账户」自助；不行的走客服邮箱
- **客服邮箱**：qtvq@qtvq.cn

## 附：几条必须记住的常识

1. **静态收款码永远无法自动到账** —— 这是微信/支付宝的机制，不是系统缺陷；只有"在线支付"能自动。
2. **对公银行汇款也无法自动确认** —— 要自动需要与银行签约"银企直连"，属商务接入而非软件开发。
3. **运营口令是两个不同的东西**：
   - 付款核实页口令 = `D:\qtvq\.dev.vars` 的 `PAYMENT_ADMIN_KEY`
   - 运营台（钱包入账）口令 = `server/.env` 的 `ADMIN_KEY`
4. **别把口令写进聊天/邮件**；口令已是你账号资金与会员的控制权。
